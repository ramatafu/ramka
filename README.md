# ramka — Stage 1 (локальный зашифрованный чат по LAN)

## О проекте

`ramka` — приватный P2P-мессенджер для Android. Идея: два человека в одной
локальной сети должны иметь возможность переписываться, не проходя ни через
какой сервер вообще, с шифрованием, которое проверяемо аутентифицирует
собеседника (а не просто "шифрует трафик до кого-то"). Единственный источник
истины по функциональности и ограничениям — `PROJECT_SPEC.md` в корне репозитория;
этот README описывает конкретно то, что реализовано на Stage 1, и как это
проверить руками.

Текущий статус: Stage 1 (локальный LAN-чат, без сервера, без очереди
недоставленных сообщений — это Stage 2). Список того, что уже сделано, что
упрощено и почему — см. разделы ниже и **`DEVIATIONS.md`**.

## Модель угроз (кратко)

Это не полный анализ (полный — задача отдельного security review, см. D-1 в
DEVIATIONS.md), а краткая ориентировка: от чего Stage 1 защищает и от чего — нет.

**Защищает от:**
- Прослушивания содержимого сообщений в локальной сети (сквозное шифрование Noise IK).
- Подмены собеседника (взаимная аутентификация по Ed25519, верификация отпечатков ключей).
- (Этап 2.5) Вывода о типе и размере сообщения по длине кадра: тело перед шифрованием
  выравнивается до корзин (128…4096 байт, выше — кратно 4096), поэтому ACK и короткий
  текст имеют одинаковый размер (148 байт для корзины 128, без байта типа и счётчика).
- (Этап 2.5) Идентификации устройства по статическому ключу в рукопожатии (M1/M2/M3 зашифрованы).
- (Этап 2.5) Распознавания типа кадра и длины по открытым байтам (сигнатуры сняты).

**Не защищает от:**
- Компрометации устройства (ключи хранятся в Android Keystore, но если устройство в руках злоумышленника — игра окончена).
- Атак на уровне операционной системы (keylogging, скриншоты).
- (Этап 2.5) Некоторых остаточных метаданных: структура «соединение на сообщение» из четырёх кадров (D-3), фиксированный TCP-порт, mDNS-сервис `_ramka._tcp.` (отключаемый), тайминги ACK и повторов Outbox (сглажены джиттером, но факт соединения виден). Что именно и по какому плану снимается — в DEVIATIONS.md.
- Компрометации долговременного ключа ответчика (позволяет расшифровать M1 в записанном трафике, см. D-4).

## Что реализовано (Stage 1 + Этап B + Этап 2.5)

- **Криптография:** Noise IK-рукопожатие (X25519 + ChaCha20-Poly1305 + Ed25519), реализованное вручную поверх Bouncy Castle (см. D-1).
- **Сеть:** LAN-обнаружение через NSD (mDNS) со случайным эфемерным именем сервиса, плюс ручной ввод по QR-коду. Защищённый TCP-канал с `soTimeout` (10 с на handshake, 30 с idle).
- **Доставка:** Outbox с экспоненциальным backoff (30 с … 1 ч, с джиттером ±20%) через WorkManager и Foreground Service (`specialUse`).
- **Статусы:** Разделение SENT (успешное рукопожатие) и DELIVERED/READ (по факту получения ACK).
- **Уведомления:** Системные уведомления с вибрацией, корректный счётчик непрочитанных (badge), скрытие содержимого на заблокированном экране.
- **Защита от анализа трафика (Этап 2.5):** FramePadding (выравнивание размеров), шифрование метаданных рукопожатия (D-4), снятие сигнатур с кадров (фиксированные размеры 80/112/80 для рукопожатия, корзина+16 для данных, без типа и счётчика), джиттер для ACK, тумблер mDNS в настройках.

## Архитектура проекта

ramka/
├── app/        — UI (Jetpack Compose), ViewModels, Hilt DI, настройки, уведомления
├── domain/     — бизнес-логика, use cases, модели (AppMessage, Contact, Message), репозитории (интерфейсы)

├── network/    — LAN-обнаружение (NSD), защищённый TCP-канал (рукопожатие + доставка)
├── crypto/     — Noise IK (IkHandshake), SessionCipher, KeyManager, SecureKeyStore, FramePadding
└── storage/    — Room DAO, миграции БД


## Как проверить вручную

1. **Установка:** Соберите и установите APK на два устройства в одной Wi-Fi сети.
2. **Сопряжение:** На устройстве A нажмите «+», отсканируйте QR-код с устройства B. Проверьте отпечатки ключей.
3. **Отправка:** Напишите сообщение на A. На B оно должно появиться мгновенно.
4. **Статусы:** На A значок у сообщения должен стать ✓ (пришёл DELIVERED-ACK).
5. **Прочтение:** Откройте чат на B — у A значки меняются на ✓✓ (один READ-ACK на все неподтверждённые).
6. **Офлайн-доставка:** Выключите Wi-Fi на B, отправьте сообщение с A. Включите Wi-Fi на B — сообщение доставится, статус обновится.
7. **Backoff:** С выключенным Wi-Fi на B наблюдать (в отладочной сборке) паузы между попытками отправки (30 с, 1 мин, 2 мин... с джиттером).
8. **Уведомления:** Сверните приложение на B, отправьте сообщение с A. Должно прийти уведомление «ramka — Новое сообщение» с вибрацией.
9. **Настройки:** Зайдите в настройки на B, выключите «Автообнаружение в сети (mDNS)». С устройства A (или ноутбука) сервис `_ramka._tcp.` должен перестать обнаруживаться, но отправка по старому QR-адресу (если он сохранён) или ручному вводу IP:порт должна продолжать работать.

## Известные ограничения и отклонения

Полный список и обоснования — в **`DEVIATIONS.md`**. Кратко:
- Рукопожатие реализовано вручную, а не через noise-java (D-1).
- Нет Double Ratchet, ключи сессии статичны в рамках одного соединения (D-2).
- Одно сообщение = одно TCP-соединение с полным рукопожатием (D-3).
- Этап 2.5 в основном завершён: реализованы фиксированные кадры рукопожатия (80/112/80) и данных (корзина+16) без типа и счётчика, джиттер ACK/Outbox, soTimeout на входящих соединениях, тумблер mDNS. Остался опциональный фиктивный трафик (DEVIATIONS.md, 2.5-5).

## Сборка и разработка

- **Минимальная версия Android:** API 26 (Android 8.0)
- **Целевая версия:** API 34 (Android 14)
- **Язык:** Kotlin 1.9+
- **Сборка:** `./gradlew assembleDebug`

**Известные warnings при сборке:**
1. Неиспользуемый импорт `X25519PublicKeyParameters` в `KeyManager.kt` (можно удалить).
2. `Deprecated in Java` для методов `NsdManager.resolveService` и `serviceInfo.host` (Google планирует обновить NSD API, но текущий код работает стабильно на API 34).
3. `Parameter 'contactId' is never used` и `'Send: ImageVector' is deprecated` в `ChatScreen.kt` (косметические замечания Compose).
4. `@file:Suppress("DEPRECATION")` в `SecureKeyStore.kt` (библиотека `androidx.security:security-crypto` помечена как deprecated с версии 1.1.0, официальной замены пока нет).
